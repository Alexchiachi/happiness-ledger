# 幸福影響力記帳本 · 中國大陸版建置規格

> **這份文件的用途**：交給 AI 或開發者，據以在中國大陸境內獨立建置一套「幸福影響力記帳本」。
> 該版本自行運作、自行呈現，並定期把紀錄匯出，併入現有的開源帳本
> [`Alexchiachi/happiness-ledger`](https://github.com/Alexchiachi/happiness-ledger)。
>
> **請完整讀完第三節「資料契約」再開始動工。** 那一節是唯一不可自行更動的部分；
> 其餘皆為建議。契約若偏離，日後的資料合併會失敗。
>
> **搭配閱讀**：[`LEDGER_PROTOCOL.md`](./LEDGER_PROTOCOL.md) —— 兩本帳本之間的角色分工、
> 交接流程、交握訊息格式與契約變更程序。本文件講「蓋什麼」，那份講「怎麼協作」。

---

## 一、為什麼需要另做一套

現有帳本的存入流程會經過 `script.google.com`（Google Apps Script）。該網域在中國大陸無法連線，
因此大陸的訪客可以開啟網頁、卻無法送出紀錄。

已評估但不採用的做法：

| 做法 | 不採用的原因 |
| :--- | :--- |
| 把中繼換到大陸雲端，直接呼叫 GitHub API | 中繼自身出境連 `api.github.com` 同樣不穩定，只是把失敗往後移一步 |
| 中繼部署在香港區域 | 連通性無保證，仍受國際線路影響 |
| 自訂網域 + 境內主機 | 需要 ICP 備案，是實際的行政流程 |

因此改採**兩套獨立帳本 + 定期單向遷移**：大陸版完全在境內運作，不依賴任何境外服務；
遷移由台灣端主動拉取匯出檔並寫入，方向由境外往境內讀取，不受限制。

---

## 二、你要做的東西

一個網頁應用，讓任何人**免登入**留下一則生活中的微小覺察或善意，並看見別人留下的紀錄。

**必須具備**

1. 一個表單：稱呼、幸福微類型、感知內容
2. 一面卡片牆：呈現已收錄的紀錄，新到舊排序
3. 一個匯出功能：產生符合第三節格式的 JSON（管理者使用即可，不需公開）

**明確不需要**

- 使用者註冊、登入、帳號系統
- 按讚、留言、追蹤等社交功能
- 與 GitHub 的任何連線 —— **大陸版不應嘗試呼叫 GitHub，那正是要避開的環節**

## 三、資料契約（唯一不可更動的部分）

匯出檔是一個 JSON 陣列，每個元素是一筆紀錄：

```json
[
  {
    "id": "cn-20260915-0042",
    "source": "cn",
    "date": "2026-09-15T23:30:00+08:00",
    "author": "昆明旅人",
    "category": "🍃 自然連結",
    "content": "清晨的翠湖，霧還沒散。"
  }
]
```

### 欄位定義

| 欄位 | 型別 | 必填 | 規則 |
| :--- | :--- | :--- | :--- |
| `id` | string | ✅ | 該筆紀錄在大陸版中的唯一編號。**必須是字串，不可是數字。**建立後永久不變，絕不重複使用 |
| `source` | string | ✅ | 固定填 `"cn"`。小寫英數字，1–16 字元 |
| `date` | string | ✅ | 使用者實際送出的時刻，ISO 8601 且**必須帶時區**（`+08:00` 或 `Z`）|
| `author` | string | ✅ | 使用者填寫的稱呼，最長 40 字 |
| `category` | string | ✅ | 幸福微類型，見下方清單 |
| `content` | string | ✅ | 感知內容純文字，最長 2000 字。換行用 `\n` |

### 三條必須遵守的規則

**① `id` 一定要是字串，而且不能只是流水號數字。**

現有帳本的 `id` 是 GitHub 的 Issue 編號（整數）。大陸版若產生 `1`、`2`、`3`，合併時會與既有紀錄相撞、
互相覆蓋。建議格式 `cn-<日期>-<序號>`，例如 `cn-20260915-0042`。

**② `date` 一定要帶時區。**

這是整份契約中最容易出錯、後果也最難補救的一項。缺少時區的字串會被當成 UTC 解讀，
大陸使用者在晚上十一點半存入的紀錄，會變成當天早上七點半 —— 甚至跳到前一天。

**這個時間戳代表當事人真正停頓下來的那一刻，遷移時會被完整保留，而不是被遷移作業當天的時間覆蓋。**
對一本記錄「當下」的帳本，這是核心，不是細節。

**③ 匯出必須是完整快照，可重複匯出。**

每次匯出包含全部紀錄即可，不需要自行計算增量。遷移工具會依 `source` + `id` 自動略過已匯入的紀錄，
所以重複匯出同一批資料是安全的，不會產生重複。

### 幸福微類型

下拉選單提供這四項固定選擇（emoji 是內容的一部分，請照抄）：

```
☕ 五感覺察
🤝 微小善意
🍃 自然連結
🧘 身心安頓
```

另提供「其他」選項，讓使用者自行填寫。自訂類型請在前面加上 `✨ ` 前綴後寫入 `category`，
例如使用者輸入「手作烘焙」，則 `category` 為 `"✨ 手作烘焙"`。

## 四、前端要求

**文案語言**：介面使用**簡體中文**。現有帳本是繁簡雙語，大陸版不必比照，簡體單語即可。

**必要行為**

- 送出成功後清空表單並給予明確回饋；**送出失敗時不可清空表單**，使用者寫的字必須保留
- 狀態要說真話：寫入成功才顯示成功，失敗要能看出是失敗
- 卡片牆依 `date` 新到舊排序
- 紀錄內容以純文字呈現，**務必轉義後再插入 DOM**，不可直接當 HTML 渲染

**防濫用（三層，都必須有）**

1. **蜜罐欄位**：表單中放一個 CSS 隱藏的輸入框。真人看不到不會填，機器人會填。有值就靜默丟棄，**不要回報失敗**，否則對方會換方法再來
2. **前端節流**：同一瀏覽器兩次送出間隔至少 30 秒
3. **伺服端過濾**：內容少於 10 字、或含有外部商業連結者，暫緩收錄。**這一層必須在伺服端，前端的檢查一律可被繞過**

## 五、內容準則

沿用開源帳本的共創原則。這些是收錄標準，請寫進頁面說明，並作為伺服端過濾與人工審核的依據。

**收錄（四要）**

1. **真實微小** —— 一杯茶的溫度、晨光裡的呼吸、一句真誠的道謝
2. **當下覺察** —— 個人的五感體驗與內在安頓
3. **無私善意** —— 給予他人的微小溫暖、對土地與環境的友善舉動
4. **利他留白** —— 文字簡約真誠，留給讀者平靜與力量

**不收錄（四不）**

1. **不炫耀比較** —— 外在物質或財富的攀比
2. **不說教批判** —— 道德指責、政治爭論或負面宣洩
3. **不商業廣告** —— 推銷、導流連結或商業宣傳
4. **不散布仇恨** —— 謾罵、攻擊性或引起焦慮的文字

## 六、技術選型（建議，非強制）

只要能產出第三節的匯出檔，怎麼實作都可以。

| 層 | 建議 | 說明 |
| :--- | :--- | :--- |
| 前端 | 靜態 HTML / CSS / JS | 現有帳本是單一 `index.html`，無框架、無建置流程 |
| 後端 | 騰訊雲 CloudBase 雲函數，或阿里雲函數計算 | 都提供瀏覽器內編輯器與 HTTP 觸發，最接近原本的 Apps Script |
| 資料 | 對應雲端的內建資料庫 | 紀錄量小，不需要獨立資料庫 |

**注意**：使用境內雲端資源、綁定自訂網域通常需要 ICP 備案，且帳號需實名認證。
**這些行政條件請在動工前先確認**，不要蓋到一半才發現卡住。

## 七、遷移如何進行（了解下游即可，不需實作）

```
大陸版帳本
    │  管理者匯出 JSON
    ▼
匯出檔.json
    │  台灣端執行 tools/import-records.js
    ▼
逐筆建立 GitHub Issue（每筆間隔數十秒）
    │  觸發既有的 record-to-ledger 流程
    ▼
data/records/*.md ＋ data/ledger.json ＋ GitHub Pages
```

遷移工具會：

- **整批驗證**匯出檔，任一筆不合格就整批不匯入 —— 寧可一筆都不做，也不要做一半
- 依 `source` + `id` 略過已匯入者，重跑安全
- 逐筆間隔送出，避免推送競爭與速率限制
- 把原始 `date`、`source`、`id` 一併保留在最終紀錄中

**大陸版不需要為遷移做任何事，只要匯出檔符合契約即可。**

## 八、驗收標準

交付前請逐項確認：

- [ ] 未登入的訪客可以完成一次存入
- [ ] 送出失敗時，使用者寫的內容仍在表單中
- [ ] 卡片牆依時間新到舊排列
- [ ] 匯出檔通過驗證：`node tools/import-records.js 匯出檔.json --dry-run`
- [ ] 所有 `id` 皆為字串，且格式不可能與整數混淆
- [ ] 所有 `date` 皆帶時區；抽查一筆，換算後與實際存入時間相符
- [ ] 蜜罐、節流、伺服端過濾三層皆在
- [ ] 含 `<script>` 或 HTML 標籤的內容，在卡片牆上以純文字顯示，未被當作標記執行
- [ ] 大陸版全程未呼叫任何境外服務

最後一項可以這樣驗：在開發者工具的網路分頁重新載入並完成一次存入，
確認沒有任何指向境外網域的請求。

## 九、有疑問時

契約（第三節）以外的部分都可以依實際情況調整。**契約本身若需要變更，請先提出討論**——
它是兩套帳本之間唯一的介面，單方面更動會讓遷移在無聲中出錯。
